    What is machine learning?#

    Machine learning (ML) is a subfield of artificial intelligence that lets computers learn from data without being explicitly programmed

    Artificial intelligence is the broad goal of making computers do tasks that seem to need intelligence. Machine learning is the part of AI where the computer learns how to do a task from examples, instead of following rules written by a person.

    Herbert Simon: “Learning is any process by which a system improves performance from experience.”

    Herbert Simon was an American scientist and Nobel laureate in economics, and a founder of AI. His definition applies to people and machines alike: learning means getting better with experience.

    Tom Mitchell (1997): a computer program learns from experience \(E\) with respect to a task \(T\) and performance measure \(P\) if its performance on \(T\), measured by \(P\), improves with experience \(E\)

    Mitchell's definition makes Simon's precise. To say a program learns, name three things: the task it does (\(T\)), how its success is measured (\(P\)), and the experience it learns from (\(E\), usually data). Learning means that \(P\) improves as \(E\) grows.

    Example: \(T\) (task): label a motor as healthy or faulty from its vibration signal. \(P\) (performance): fraction labelled correctly. \(E\) (experience): past vibration records labelled by technicians

    A worn bearing or loose mounting changes how a motor vibrates. The task is to label each motor from an accelerometer signal. The performance is the fraction labelled correctly. The experience is past records for which a technician later confirmed whether the motor was healthy or faulty. This is the fault-detection problem several students named in the survey.

    Symbols

    \(T\)Task: what the program must do.
    \(P\)Performance measure: how success is scored.
    \(E\)Experience: the data the program learns from.

    Why machine learning?#

    Diagram: traditional programming: data + rules \(\to\) program \(\to\) answers. Machine learning: data + answers \(\to\) learning \(\to\) rules (model)

    In traditional programming a person writes the rules, and the computer applies them to data to produce answers. In machine learning we give the computer data together with the correct answers, and it works out the rules itself.

    Rules are hard to write by hand. What rule tells a worn bearing from a healthy one in a vibration signal?

    An experienced technician can hear a failing bearing, but writing precise rules in terms of thousands of signal samples is almost impossible. Learning from many labelled signals works much better.

    Too much data. A factory with hundreds of sensors, each sampled many times per second, produces far more data than anyone can read

    For example, 500 sensors sampled 100 times per second give \(500 \times 100 \times 86\,400 \approx 4.3\) billion readings per day. Only an automatic method can watch them all.

    Systems change. Detectors age and sensors drift; a learned model can be retrained on new data

    Hand-written rules must be rewritten when conditions change; a learned model is simply retrained on new data.

    Model: the rules the computer learns; it turns inputs into answers

    The word model is used on almost every slide from now on, so it is defined here. Once learned, a model is applied to new data like a traditional program.

    ML in a nutshell: three components#

    Every ML method can be described by three choices. We use this framework in every lecture.

    Representation: how do we turn raw data into numbers a model can use? A vibration signal \(\to\) amplitudes at 1000 frequencies. A camera image \(\to\) pixel values. A smart meter \(\to\) kWh used in each hour

    A computer model needs numbers. Representation is how raw measurements become a list of numbers for each object. A vibration signal becomes 1000 amplitudes, one per frequency (its Fourier spectrum); an image becomes its pixel values; a smart meter's record becomes 24 numbers per day, the energy used in each hour. The term also covers the family of models we allow, for example all straight lines.

    Evaluation: how do we know the model is good? Give it a score: for a number, the average squared error (later today); for a category, the fraction labelled correctly. Always scored on data the model has not seen

    We need a number that scores a model. For numerical outputs, the mean squared error (slide 32). For categories, the fraction labelled correctly, called the accuracy (slide 37); Lecture 3 adds other scores. The crucial rule: score the model on new data, not on the data used to train it (slide 34).

    Optimisation: how do we find the best model? Change the model's adjustable numbers (its parameters) step by step to reduce the error: gradient descent (Lecture 2). Keep the model simple: regularisation (Lecture 4)

    A parameter is a number inside the model that is learned from data, for example the slope of a straight line. Optimisation searches for the parameter values with the best score. Gradient descent repeatedly adjusts the parameters in the direction that reduces the error. Regularisation adds a penalty for complexity so that the model does not fit the noise. Only the names are needed today.

    Observation: one measured example (also: data point, reading, sample); example: one reading of the panel

    One row of the data table.

    Input: a quantity we measure and use to predict (also: variable, feature, predictor); example: sunlight, cell temperature

    Statisticians say predictor or independent variable; computer scientists say feature.

    Output: the quantity we want to predict (also: response, target); example: electrical power

    Also called the dependent variable.

    Label: the known, correct output of an observation; example: the power actually measured

    In the training data the output is known; that known value is the label. “Labelled data” means data with these known outputs. The word is used most for categories (“healthy”, “faulty”), but it applies to numbers too.

    Model: the rule that turns inputs into a predicted output; example: power \(\approx\) a formula in sunlight and temperature

    As on slide 17.

    Parameter: an adjustable number inside the model, learned from data; example: how many watts per W/m\(^2\)

    For the panel, one parameter says how much the power rises for each extra W/m\(^2\) of sunlight.

    Training data: observations used to fit the model; example: last month's readings. Test data: new observations kept aside to check the model; example: this week's readings

    “Fit” and “train” mean the same thing: choose the parameters from data. The test data are not used in fitting, so they show how the model does on data it has never seen. This split is the subject of slide 34.

    Types of machine learning#

    TypeWhat it learns fromExample
    Supervisedlabelled data: inputs with their known outputspredict a building's electricity use (kWh) from temperature and time of day
    Unsupervisedunlabelled data: inputs only; find groups or structuregroup smart-meter customers by their daily load profile, with no labels given
    Reinforcementtrial and error: actions earn rewards from an environmentlearn when to switch a heater on and off to hold a room at a set temperature

    Supervised: labelled data: inputs with their known outputs. Example: predict a building's electricity use (kWh) from temperature and time of day

    Supervised learning learns from examples where the correct answer is known, like a student with a teacher. Past meter readings give the correct kWh for many hours with known temperature and time; a model trained on them predicts the use for new hours.

    Unsupervised: unlabelled data: inputs only; find groups or structure. Example: group smart-meter customers by their daily load profile, with no labels given

    No correct answers are given; the method finds patterns by itself. Given each customer's 24 hourly readings, it can group customers with similar daily patterns (for example households, shops, night-time businesses).

    Reinforcement: trial and error: actions earn rewards from an environment. Example: learn when to switch a heater on and off to hold a room at a set temperature

    An agent acts, receives a reward or penalty, and learns which actions lead to good outcomes. The controller switches the heater, is rewarded when the room is close to the set temperature and penalised for energy used, and learns a good switching policy. SPM 405 covers supervised and unsupervised learning; reinforcement learning is mentioned for completeness.

    Reward: a score the environment gives after each action

    The reward is to reinforcement learning what the label is to supervised learning: the signal the method learns from.
