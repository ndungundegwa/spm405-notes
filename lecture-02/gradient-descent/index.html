    Gradient descent#

    For linear regression the normal equations give the best coefficients directly. Most later models (logistic regression, neural networks) have no such formula; they are trained by gradient descent, which walks downhill on the error step by step. We learn it here, on linear regression, because the right answer is already known, so we can watch the method find it.

    Notation on this page

    SymbolRead asMeaning
    \(\ell_i\)“ell i”loss of data point \(i\): how wrong the model is on that one point
    \(J(\boldsymbol\beta)\)“J of beta”cost: the average loss over all \(n\) points; it depends on the coefficients \(\boldsymbol\beta\)
    \(\alpha\)“alpha”step size, also called the learning rate; chosen by us

    Loss and cost#

    Two words appear in every later lecture and in every software library, often used loosely.

    The loss says how wrong the model is on one data point. For regression we use half the squared residual:

    \[ \ell_i = \tfrac12\,\bigl(y_i - \hat y_i\bigr)^2 . \]

    The cost is the average loss over all \(n\) points, one number for the whole data set:

    \[ J(\boldsymbol\beta) = \frac1n \sum_i \ell_i = \frac{1}{2n} \sum_i \bigl(y_i - \hat y_i\bigr)^2 . \]

    The cost depends on the coefficients \(\boldsymbol\beta\): change \(\boldsymbol\beta\), the line moves, and \(J\) changes. Dividing by \(n\) keeps the numbers of similar size whatever the size of the data set; the \(\tfrac12\) only cancels the 2 that appears when we differentiate.

    Training a model means finding the \(\boldsymbol\beta\) with the smallest cost. This is true of every model in the course; only the form of the loss changes (Lecture 3 uses a different loss for classification).

    Since \(J = \mathrm{RSS}/2n\) and dividing by a fixed number does not move the minimum, the best line is the same as the least-squares line. (Many books and libraries say “loss” for both meanings; in these notes loss is for one point and cost for the average.)

    Example. Three points with residuals \(1, -2, 3\) have losses \(\tfrac12 \times 1^2 = 0.5\), \(\tfrac12 \times (-2)^2 = 2\) and \(\tfrac12 \times 3^2 = 4.5\), so the cost is \(J = (0.5 + 2 + 4.5)/3 = 2.33\). Check: \(\mathrm{RSS} = 1 + 4 + 9 = 14\) and \(\mathrm{RSS}/2n = 14/6 = 2.33\).

    Walk downhill#

    The algorithm:

    1. Start with any \(\boldsymbol\beta\) (for example all zeros).
    2. Repeat: \[ \boldsymbol\beta_{\text{new}} = \boldsymbol\beta_{\text{old}} - \alpha\,\nabla J . \]
    3. Stop when the cost \(J\) no longer falls.

    The gradient \(\nabla J\) points uphill, in the direction in which the cost rises fastest; a step against it goes downhill. The step size \(\alpha\) sets how far each step goes. Because the step is \(\alpha\) times the slope, steps shrink automatically as the slope flattens near the minimum: big steps where the cost is steep, small steps near the bottom.

    \(\alpha\) is our first example of a hyperparameter: a setting that we choose, rather than one that is fitted from the data (Lecture 4 says more).

    What is the gradient?#

    With one coefficient, \(\nabla J\) is just the ordinary derivative \(dJ/d\beta\), the slope of the cost curve.

    • If the slope is negative, the cost falls to the right, so we should increase \(\beta\).
    • If the slope is positive, we should decrease \(\beta\).

    The minus sign in the update does exactly this: \(-\alpha \times (\text{negative slope})\) is a step to the right, towards the minimum.

    With many coefficients, the gradient is a list of slopes, one per coefficient:

    \[ \nabla J = \left(\frac{\partial J}{\partial\beta_0}, \frac{\partial J}{\partial\beta_1}, \dots, \frac{\partial J}{\partial\beta_p}\right). \]

    Each partial derivative \(\partial J/\partial\beta_j\) is the slope of \(J\) when only \(\beta_j\) changes and the others are held fixed. Together they point in the steepest uphill direction.

    Worked example. Take \(J = (\beta - 2)^2\), whose minimum is at \(\beta = 2\), with \(\alpha = 0.2\). The slope is \(dJ/d\beta = 2(\beta - 2)\).

    • Start at \(\beta = 0\): slope \(-4\), so \(\beta_{\text{new}} = 0 - 0.2 \times (-4) = 0.8\).
    • At \(\beta = 0.8\): slope \(2(0.8 - 2) = -2.4\), so \(\beta = 0.8 + 0.2 \times 2.4 = 1.28\).
    • At \(\beta = 1.28\): slope \(-1.44\), so \(\beta = 1.568\), and so on towards 2.

    Each step removes 40% of the remaining distance to 2, because \(\beta - 2\) is multiplied by \(1 - 2\alpha = 0.6\).

    Gradient descent for linear regression#

    For the cost \(J(\boldsymbol\beta) = \frac{1}{2n}\sum_i (y_i - \hat y_i)^2\) of linear regression, the gradient is \(\nabla J = -\frac1n\mathbf X^{\mathsf T}(\mathbf y - \mathbf X\boldsymbol\beta)\), where \(\mathbf y - \mathbf X\boldsymbol\beta\) is the column of residuals. There are two common versions of the update.

    Batch gradient descent uses all data points in each step:

    \[ \boldsymbol\beta \leftarrow \boldsymbol\beta + \frac{\alpha}{n}\,\mathbf X^{\mathsf T}\bigl(\mathbf y - \mathbf X\boldsymbol\beta\bigr). \]

    Stochastic gradient descent uses one data point \(i\) in each step, cycling through the data:

    \[ \boldsymbol\beta \leftarrow \boldsymbol\beta + \alpha\,\bigl(y_i - \hat y_i\bigr)\,x_i . \]

    Each stochastic step is cheap, which is why this version is used for very large data sets and for neural networks. The arrow \(\leftarrow\) means “becomes”, as in a program: compute the right-hand side, then store it in \(\boldsymbol\beta\).

    Reading the update. The step is proportional to the error \(y_i - \hat y_i\): a big mistake gives a big correction, a small mistake a small one. When a prediction is too low, the coefficients move so as to raise it, in proportion to the input values.

    Good news for linear regression: the cost is a quadratic function of \(\boldsymbol\beta\), a single bowl with only one minimum (it is convex). Walking downhill always leads to the one best answer. Neural networks do not have this property.

    Example: one step of gradient descent by hand#

    Fit \(y = \beta x\) (no intercept) to the points \((1, 2.2), (2, 3.9), (3, 6.1)\) with cost \(J(\beta) = \frac{1}{n}\sum_i (y_i - \beta x_i)^2\). Start at \(\beta = 1\) with step size \(\alpha = 0.05\). Do one gradient-descent step. What is the exact minimiser?

    Solution triple-click to reveal
    \[ \frac{dJ}{d\beta} = -\frac{2}{n}\sum_i x_i (y_i - \beta x_i) = -\frac{2}{3}\big[1(1.2) + 2(1.9) + 3(3.1)\big] = -9.533 \]

    Update: \(\beta \leftarrow 1 - 0.05 \times (-9.533) = 1.4767\).

    Exact minimiser (set the derivative to zero): \(\beta = \sum x_i y_i / \sum x_i^2 = 28.3/14 = 2.0214\). One step moved from 1 to 1.4767, towards 2.0214.

    Choosing the step size \(\alpha\)#

    We run gradient descent on the temperature-sensor calibration data of simple linear regression (with the temperature standardised, as explained in the next section), starting from \(\boldsymbol\beta = 0\), where the cost is \(1.49 \times 10^5\) mV\(^2\).

    • Too small (\(\alpha = 0.01\)): very slow. After 40 steps the cost has only fallen to \(6.7 \times 10^4\) mV\(^2\).
    • About right (\(\alpha = 0.5\)): the cost reaches its minimum, 114 mV\(^2\), by step 10, and the coefficients equal the least-squares values (9.832 mV/\(^\circ\)C and 2.54 mV).
    • Too large (\(\alpha = 2.1\)): each step jumps past the minimum to a higher point on the other side, and the cost grows without limit.

    Always plot the cost at every step. It must go down. This is the simplest check that both the code and the step size are right.

    Worked numbers

    Minimum cost \(= \mathrm{RSS}/(2n) = 4562/40 = 114\) mV\(^2\). Cost at steps 0, 1, 2, 3 with \(\alpha = 0.5\): 149 435; 37 444; 9 447; 2 447 mV\(^2\), about four times smaller each step. With a standardised input, \(\mathbf X^{\mathsf T}\mathbf X/n\) is the identity matrix, so \(\alpha = 1\) would reach the minimum in one step, and any \(\alpha > 2\) diverges.

    Scale the inputs first#

    With the raw temperatures (6 to 93 \(^\circ\)C) only tiny steps are possible: even after 5000 steps the offset is still wrong (1.4 mV instead of 2.5 mV). The reason is the shape of the cost. With raw inputs the cost bowl is a long, narrow valley: very steep in the slope direction (temperatures are large numbers) and very flat in the intercept direction. A step size small enough not to blow up across the valley (at most \(6.5 \times 10^{-4}\) here) is far too small to make progress along it.

    The cure is to standardise each input: subtract its average and divide by its standard deviation \(s\),

    \[ z = \frac{x - \bar x}{s} . \]

    Every standardised input has average 0 and spread 1, so all directions of the bowl become equally steep, and about 10 steps are enough.

    Rules.

    • Standardise the inputs before gradient descent.
    • Compute \(\bar x\) and \(s\) from the training data only, and scale the test data with those same numbers, so that no information about the test data leaks into training.

    Sensor inputs often differ by many orders of magnitude (W/m\(^2\), \(^\circ\)C, mV, kHz), so scaling is a routine first step. In the solar data, \(G\) is in hundreds and \(T\) in tens; in a vibration data set, frequencies may be in kHz.

    Worked numbers

    For the calibration temperatures \(s = 28.1\) \(^\circ\)C. After fitting on \(z\), convert back: slope per \(^\circ\)C \(= \beta_z/s = 276.03/28.075 = 9.832\) mV/\(^\circ\)C; offset \(= \beta_{0z} - 9.832 \times 47.71 = 471.64 - 469.10 = 2.54\) mV, the least-squares values.

    Summary of Lecture 2#

    1. Least squares chooses the line with the smallest residual sum of squares.
    2. Standard errors, \(t\) and \(p\) say how much to trust each coefficient; RSE and \(R^2\) say how well the model fits.
    3. With many inputs, \(\mathbf X^{\mathsf T}\mathbf X\,\hat{\boldsymbol\beta} = \mathbf X^{\mathsf T}\mathbf y\). Each coefficient holds the other inputs fixed.
    4. Categories enter as dummy variables; products of inputs give interactions; logarithms can straighten curves.
    5. Gradient descent finds the same answer step by step: standardise the inputs first, and watch the cost fall.
