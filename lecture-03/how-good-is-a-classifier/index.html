    How good is a classifier?#

    The error rate of Lecture 1 counts mistakes, but it does not say which mistakes a classifier makes, and in practice the two kinds of mistake can have very different costs. This page introduces the confusion matrix, the measures built from it, the choice of threshold, and the ROC curve. The example is the two-sensor machine classifier of the previous page, judged on its 2000 test machines.

    Notation on this page

    Four kinds of outcome#

    Every decision of a two-class classifier falls in one of four boxes. Each box is named by two words:

    • Positive / negative is what the model said. Positive means class 1, the thing we are looking for (here, faulty). “Positive” does not mean “good”: it means the model raised the alarm.
    • True / false says whether the model was right.
    model saysreally isname
    TPfaultyfaultytrue positive
    FPfaultyhealthyfalse positive
    FNhealthyfaultyfalse negative
    TNhealthyhealthytrue negative

    The first word judges the model; the second repeats what it said. So there are two kinds of mistake: a false positive is a false alarm, and a false negative is a missed fault. For example, a healthy machine flagged as faulty is an FP; a faulty machine passed as healthy is an FN. In maintenance these have very different costs.

    The confusion matrix#

    A confusion matrix is a table that counts the four outcomes on the test set. It is the standard summary of a classifier's performance, and it is always computed on test data, not on the data used for fitting.

    predicted positivepredicted negative
    truly positiveTPFN
    truly negativeFPTN

    Rows are the true class, columns the predicted class. The diagonal holds the correct decisions; off the diagonal are the mistakes. (This is the layout of ISLP and of scikit-learn's confusion_matrix; some books swap rows and columns, so always check the labels.) The table shows not only how many mistakes the model makes but which kind: which class it “confuses” with which. Two models with the same number of mistakes can make very different kinds.

    The machines (2000 test machines, threshold 0.5):

    predicted faultypredicted healthytotal
    truly faulty416 (TP)177 (FN)593
    truly healthy49 (FP)1358 (TN)1407
    total46515352000

    Row totals are what is really there; column totals are what the model said. The model caught 416 faults, missed 177, raised 49 false alarms and left 1358 healthy machines alone. That is \(177 + 49 = 226\) mistakes out of 2000, an error rate of 0.113.

    Measures built from the confusion matrix#

    NameAlso calledFormulaMachines
    accuracy\((\mathrm{TP} + \mathrm{TN})/\text{all}\)\((416 + 1358)/2000 = 0.887\)
    recallsensitivity, detection rate, TPR\(\mathrm{TP}/(\mathrm{TP} + \mathrm{FN})\)\(416/593 = 0.702\)
    precisionpositive predictive value\(\mathrm{TP}/(\mathrm{TP} + \mathrm{FP})\)\(416/465 = 0.895\)
    specificitytrue negative rate\(\mathrm{TN}/(\mathrm{TN} + \mathrm{FP})\)\(1358/1407 = 0.965\)
    F1-scoreF-measure, \(F_1\)\(\dfrac{2 \times \text{precision} \times \text{recall}}{\text{precision} + \text{recall}} = \dfrac{2\,\mathrm{TP}}{2\,\mathrm{TP} + \mathrm{FP} + \mathrm{FN}}\)\(832/1058 = 0.786\)

    Here “all” \(= \mathrm{TP} + \mathrm{FN} + \mathrm{FP} + \mathrm{TN}\), the 2000 test machines.

    • Accuracy is the fraction of correct decisions.
    • Recall: of the machines that really are faulty, the fraction we catch.
    • Precision: of the machines we flag, the fraction that really are faulty.
    • Specificity: of the healthy machines, the fraction left alone.
    • F1-score: one number that is high only when precision and recall are both high.

    In words: we catch 70% of the faults; 90% of our alarms are real faults; 97% of healthy machines are left alone. The accuracy of 0.887 looks good, yet 30% of faults are missed. Which number matters depends on the application.

    Accuracy can mislead when one class is rare. If only 1% of machines are faulty, a “classifier” that calls every machine healthy is 99% accurate and catches nothing. Always look at recall and precision as well.

    The F1-score#

    It is often convenient to have a single number that rewards a classifier only if it both catches the faults (high recall) and raises few false alarms (high precision). The F1-score is the harmonic mean of precision and recall:

    \[ F_1 = \frac{2 \times \text{precision} \times \text{recall}}{\text{precision} + \text{recall}} = \frac{2\,\mathrm{TP}}{2\,\mathrm{TP} + \mathrm{FP} + \mathrm{FN}} . \]

    The second form comes from substituting precision \(= \mathrm{TP}/(\mathrm{TP} + \mathrm{FP})\) and recall \(= \mathrm{TP}/(\mathrm{TP} + \mathrm{FN})\). \(F_1\) lies between 0 and 1, and equals 1 only when there are no false positives and no false negatives.

    Why the harmonic mean, not the ordinary average? The harmonic mean is pulled towards the smaller of the two. The “classifier” that calls every machine faulty has recall 1 but, with 1% faults, precision 0.01. Its ordinary average is 0.505, which looks respectable; its F1-score is \(2 \times 0.01 \times 1/1.01 = 0.020\), which shows it is useless. The “call everything healthy” classifier has \(\mathrm{TP} = 0\), so \(F_1 = 0\), although its accuracy is 99%.

    For the machines, \(F_1 = 2 \times 416/(2 \times 416 + 49 + 177) = 832/1058 = 0.786\), between the precision (0.895) and the recall (0.702), and closer to the smaller one.

    Note that \(F_1\) ignores the true negatives entirely, and it weights a missed fault and a false alarm equally. When the two errors have very different costs, compare costs directly, as in choosing the threshold below.

    Other names

    Medicine uses sensitivity (recall) and specificity; information retrieval uses precision, recall and the F1-score. The general \(F_\beta\)-score, \((1 + \beta^2)\,\text{precision} \times \text{recall}/(\beta^2\,\text{precision} + \text{recall})\), counts recall \(\beta\) times as important as precision; \(F_1\) is the case \(\beta = 1\).

    Example: rates from a confusion matrix#

    On 200 test machines (50 faulty, 150 healthy) a classifier gives \(\mathrm{TP} = 42\), \(\mathrm{FN} = 8\), \(\mathrm{FP} = 15\), \(\mathrm{TN} = 135\). Compute the accuracy, the true positive rate (recall), the false positive rate, the precision and the F1-score.

    Solution triple-click to reveal
    • Accuracy \(= (42 + 135)/200 = 0.885\)
    • TPR (recall) \(= 42/(42 + 8) = 0.84\): 84% of faulty machines are caught.
    • FPR \(= 15/(15 + 135) = 0.10\): 10% of healthy machines raise a false alarm.
    • Precision \(= 42/(42 + 15) = 0.737\): when the alarm sounds, the machine is faulty 74% of the time.
    • F1 \(= 2 \times 42/(2 \times 42 + 15 + 8) = 84/107 = 0.785\) (check: \(2 \times 0.737 \times 0.84/(0.737 + 0.84) = 0.785\)).

    Choosing the threshold#

    The same model, the same probabilities and the same test machines give different decisions for different thresholds:

    thresholdrecallprecisionF1missed faults (FN)false alarms (FP)
    0.20.840.680.7597237
    0.50.700.900.7917749
    0.80.560.990.722614

    A low threshold catches more faults but raises more false alarms; a high threshold gives few false alarms but misses more faults. Lowering the threshold from 0.5 to 0.2 catches 80 more faults, at the price of 188 more false alarms. The F1-score is highest at 0.5, where precision and recall are most balanced; but that does not make 0.5 the best threshold, as the costs below show.

    No threshold is “correct”. Choose it by comparing the cost of a missed fault (a breakdown) with the cost of a false alarm (an unnecessary inspection).

    Worked numbers: costing the decisions

    Suppose a missed fault costs KSh 500 000 and a false alarm KSh 20 000. The total cost on the test machines is

    • threshold 0.2: \(97 \times 500\,000 + 237 \times 20\,000 = 53.2\) million;
    • threshold 0.5: \(177 \times 500\,000 + 49 \times 20\,000 = 89.5\) million;
    • threshold 0.8: \(261 \times 500\,000 + 4 \times 20\,000 = 130.6\) million.

    Because missed faults are so expensive, the low threshold is cheapest.

    The ROC curve#

    The ROC curve shows the performance at every threshold at once, using two rates:

    • the true positive rate, \(\mathrm{TPR} = \mathrm{TP}/(\mathrm{TP} + \mathrm{FN})\): the fraction of faults caught (the same as recall);
    • the false positive rate, \(\mathrm{FPR} = \mathrm{FP}/(\mathrm{FP} + \mathrm{TN})\): the fraction of healthy machines wrongly alarmed (\(\mathrm{FPR} = 1 - \text{specificity}\)).

    Both are fractions of a true class, TPR of the faulty machines and FPR of the healthy ones, so neither depends on how common faults are. For the machines at threshold 0.5, \(\mathrm{TPR} = 416/593 = 0.702\) and \(\mathrm{FPR} = 49/1407 = 0.035\).

    Each threshold gives one pair (FPR, TPR). Try every threshold from 0 to 1 and plot the points: that is the ROC curve (receiver operating characteristic, a name from radar engineering). A threshold of 1 flags nothing and gives the point \((0, 0)\); a threshold of 0 flags everything and gives \((1, 1)\).

    • A perfect classifier reaches the top-left corner: every fault caught with no false alarm.
    • Random guessing lies on the diagonal: it catches faults and raises false alarms at the same rate.

    The area under the curve (AUC) summarises the whole curve in one number: 1 for a perfect classifier, 0.5 for random guessing. For our machines, AUC = 0.89. The AUC has a neat meaning: it is the probability that a randomly chosen faulty machine gets a higher \(\hat p\) than a randomly chosen healthy one.
