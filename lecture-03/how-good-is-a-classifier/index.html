    How good is a classifier?#

    Judging a classifier: four kinds of outcome#

    model saysreally
    TPfaultyfaultytrue positive
    FPfaultyhealthyfalse positive
    FNhealthyfaultyfalse negative
    TNhealthyhealthytrue negative

    Before any numbers, the vocabulary. Every later measure of quality (accuracy, recall, precision, the ROC curve) is built from these four outcomes, so students must know them by heart.

    Two words name each outcome. Positive / negative = what the model said. Positive: class 1 (faulty, what we look for). Negative: class 0 (healthy)

    “Positive” does not mean “good”. It means the model raised the alarm: it said “faulty”.

    True / false = was the model right?

    The first word judges the model; the second word repeats what it said.

    A false positive is a false alarm. A false negative is a missed fault

    The two kinds of mistake. In maintenance they have very different costs (slide 23).

    Table: TP: says faulty, really faulty (true positive); FP: says faulty, really healthy (false positive); FN: says healthy, really faulty (false negative); TN: says healthy, really healthy (true negative). Green: correct. Red: mistakes

    Try it: Ask: a healthy machine flagged as faulty; which box? (FP.) A faulty machine passed as healthy? (FN.)

    The confusion matrix#

    predicted
    positivenegative
    truly positiveTPFN
    truly negativeFPTN

    A confusion matrix is a table that counts the four outcomes on the test set

    It is the standard summary of a classifier's performance. It is always computed on test data, not on the data used to fit.

    Rows: the true class. Columns: the predicted class. Diagonal: correct decisions. Off the diagonal: mistakes

    This is the layout of ISLP Table 4.4 and of scikit-learn's confusion_matrix. Some books swap rows and columns, so always check the labels.

    It shows not only how many mistakes the model makes, but which kind: which class it “confuses” with which

    Hence the name. Two models with the same number of mistakes can make very different kinds.

    Table: truly positive: TP, FN; truly negative: FP, TN. Each box holds a count of test machines

    How good is it?#

    NameAlso calledFormulaValue
    accuracy\((\mathrm{TP} + \mathrm{TN})/\text{all}\)0.887
    recallsensitivity; detection rate\(\mathrm{TP}/(\mathrm{TP} + \mathrm{FN})\)0.702
    precisionpositive predictive value\(\mathrm{TP}/(\mathrm{TP} + \mathrm{FP})\)0.895
    specificitytrue negative rate\(\mathrm{TN}/(\mathrm{TN} + \mathrm{FP})\)0.965

    Accuracy \(= (\mathrm{TP} + \mathrm{TN})/\text{all} = 0.887\)

    The fraction correct: \((416 + 1358)/2000 = 0.887\).

    Recall (sensitivity; detection rate) \(= \mathrm{TP}/(\mathrm{TP} + \mathrm{FN}) = 0.702\)

    Of the machines that really are faulty, the fraction we catch: \(416/593 = 0.702\).

    Precision (positive predictive value) \(= \mathrm{TP}/(\mathrm{TP} + \mathrm{FP}) = 0.895\)

    Of the machines we flag, the fraction really faulty: \(416/465 = 0.895\).

    Specificity (true negative rate) \(= \mathrm{TN}/(\mathrm{TN} + \mathrm{FP}) = 0.965\)

    Of the healthy machines, the fraction left alone: \(1358/1407 = 0.965\).

    In words: we catch 70% of the faults; 90% of our alarms are real faults; 97% of healthy machines are left alone

    Accuracy looks good, but 30% of faults are missed. Which number matters depends on the application.

    “All” \(= \mathrm{TP} + \mathrm{FN} + \mathrm{FP} + \mathrm{TN} = 2000\) test machines. Accuracy can mislead when one class is rare (see “Things to watch”)

    Beyond the slide: other names

    Medicine uses sensitivity and specificity; information retrieval uses precision and recall. The F1-score, \(2 \times\) precision \(\times\) recall/(precision \(+\) recall), combines the two: here \(2 \times 0.895 \times 0.702/1.597 = 0.787\). The false positive rate is \(1 -\) specificity \(= 0.035\) (slide 25).

    Example: rates from a confusion matrix#

    On 200 test machines (50 faulty, 150 healthy) a classifier gives \(\mathrm{TP} = 42\), \(\mathrm{FN} = 8\), \(\mathrm{FP} = 15\), \(\mathrm{TN} = 135\). Compute the accuracy, the true positive rate (recall), the false positive rate and the precision.

    Solution triple-click to reveal
    • Accuracy \(= (42 + 135)/200 = 0.885\)
    • TPR (recall) \(= 42/(42 + 8) = 0.84\): 84% of faulty machines are caught.
    • FPR \(= 15/(15 + 135) = 0.10\): 10% of healthy machines raise a false alarm.
    • Precision \(= 42/(42 + 15) = 0.737\): when the alarm sounds, the machine is faulty 74% of the time.

    Choosing the threshold#

    thresholdrecallprecisionmissedfalse
    faultsalarms

    0.50.700.9017749

    Table: threshold 0.2: recall 0.84, precision 0.68, 97 missed faults, 237 false alarms; 0.5: 0.70, 0.90, 177, 49; 0.8: 0.56, 0.99, 261, 4

    The same model and the same test machines; only the threshold changes.

    Missed faults = FN; false alarms = FP. Same model, same probabilities; only the decision rule changes

    Low threshold: catch more faults, but more false alarms. High threshold: few false alarms, but more faults missed

    Lowering the threshold from 0.5 to 0.2 catches 80 more faults, at the price of 188 more false alarms.

    No threshold is “correct”. Compare the cost of a missed fault with the cost of a false alarm

    In maintenance a missed fault can mean a breakdown; a false alarm means an unnecessary inspection. Notebook question 5 puts numbers on this.

    Worked numbers

    Notebook question 5: a missed fault costs KSh 500 000, a false alarm KSh 20 000.

    Threshold 0.2: \(97 \times 500\,000 + 237 \times 20\,000 = 53.2\) million. Threshold 0.5: \(177 \times 500\,000 + 49 \times 20\,000 = 89.5\) million. Threshold 0.8: \(261 \times 500\,000 + 4 \times 20\,000 = 130.6\) million. The low threshold is cheapest.

    The two rates on an ROC curve#

    True positive rate (TPR) = recall: \(\mathrm{TPR} = \mathrm{TP}/(\mathrm{TP} + \mathrm{FN})\) = fraction of faults caught

    The same quantity as recall on slide 22, under the name used on ROC plots.

    False positive rate (FPR): \(\mathrm{FPR} = \mathrm{FP}/(\mathrm{FP} + \mathrm{TN})\) = fraction of healthy machines alarmed. FPR \(= 1 -\) specificity

    Both rates are fractions of a true class: TPR of the faulty machines, FPR of the healthy ones. So neither depends on how common faults are.

    Machines, threshold 0.5: \(\mathrm{TPR} = 416/593 = 0.702\); \(\mathrm{FPR} = 49/1407 = 0.035\)

    Each threshold gives one pair (FPR, TPR): one point on the ROC curve

    The next slide joins the points for all thresholds.

    The ROC curve#

    Plot: TPR (faults caught) against FPR (healthy machines alarmed), with the point for threshold 0.5

    The ROC (receiver operating characteristic, a name from radar engineering) curve shows every threshold at once. Each point is one threshold: the horizontal position is the fraction of healthy machines wrongly flagged, the vertical position the fraction of faults caught. Threshold 0.5 is the red point at \((0.035, 0.702)\).

    Try every threshold from 0 to 1 and plot each (FPR, TPR) point

    Threshold 1: flag nothing, point \((0, 0)\). Threshold 0: flag everything, point \((1, 1)\).

    Perfect classifier: top-left corner. Random guessing: the dashed diagonal

    A perfect classifier catches every fault with no false alarm. A coin toss catches faults and false alarms at the same rate.

    Area under the curve (AUC): one number for the whole curve. Perfect: 1. Random: 0.5. Our machines: AUC = 0.89

    The AUC equals the probability that a randomly chosen faulty machine gets a higher \(\hat p\) than a randomly chosen healthy one.
