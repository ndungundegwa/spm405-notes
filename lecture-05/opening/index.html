    From last week: your cross-validation errors#

    Every model so far was linear in its inputs (plus products and powers we chose by hand). Today: models that find the shape themselves

    In Lecture 2 we had to decide to add \(G \times T\) or take \(\ln V\). Splines and trees discover curves and interactions from the data.

    Today's methods are new, but they are judged and tuned with the tools of Lectures 1–4. Go through the table quickly, with one example each.

    Residual: measured minus predicted, \(y_i - \hat y_i\)

    Boosting fits each new tree to the residuals of the trees so far.

    Overfitting: the model follows the noise. Variance (of a model): how much the fit changes with a different sample of data

    A single deep tree has very high variance; bagging and random forests exist to reduce it.

    Hyperparameter: a setting we choose rather than fit (degree, \(k\), \(\lambda\))

    Today's hyperparameters: the number of knots, the pruning penalty, the number of trees, \(m\), the learning rate and the tree depth.

    10-fold CV error: the test error estimated by cross-validation (Lecture 4). Bootstrap sample: \(n\) rows drawn with replacement from the data (Lecture 4)

    Bagging is built directly on the bootstrap.

    Penalty \(\lambda\): a term added to the RSS to keep a model simple; larger \(\lambda\), simpler model (ridge, Lecture 4)

    The smoothing spline uses the same idea with a curvature penalty.

    Test error, AUC: fraction of test cases misclassified; area under the ROC curve, 1 = perfect, 0.5 = guessing (Lecture 3)

    Noise variance: the error no model can remove: the best possible MSE

    For the building it is 16 kW\(^2\); every CV error today should be compared with it.
