    Recurrent networks#

    A convolutional network shares weights across space. A recurrent neural network (RNN) shares them across time: it reads a sequence one step at a time and carries a memory forward. This page explains the idea and uses it to forecast a building's electricity demand.

    Notation on this page

    SymbolMeaning
    \(t\)time step (here, hour)
    \(x_t\)input at time step \(t\) (e.g. the demand in hour \(t\))
    \(h_t\)hidden state at time \(t\): the network's memory
    \(W\), \(U\), \(b\)weights applied to the previous hidden state, weights applied to the new input, and a bias
    \(g\)activation function
    GRU, LSTMgated recurrent unit; long short-term memory: recurrent units with “gates” that remember over longer spans
    AR(1), AR(24)autoregressive models: the next value is a linear function of the last 1 (or 24) values plus noise
    kW\(^2\)unit of the test MSE (squared error of a demand in kW)

    Sequences and memory#

    A recurrent network reads a sequence \(x_1, x_2, \dots\) one step at a time. Its hidden state \(h_t\) carries a memory of what came before, and is updated at every step:

    \[ h_t = g\bigl(W h_{t-1} + U x_t + b\bigr). \]

    The new memory depends on the old memory \(h_{t-1}\) and on the new input \(x_t\) (ISLP Section 10.5). The same weights \(W\), \(U\) and bias \(b\) are used at every step: the weights are shared along time, as a CNN shares them across space. The forecast is computed from the last hidden state.

    Plain RNNs forget quickly. GRU and LSTM units add “gates”, small learned switches that decide what to keep in the memory and what to forget, so they can remember over longer spans.

    Example: forecasting a building's demand#

    The office building of Lecture 5 is metered every hour for 200 days. The task: from the last 24 hours of demand, forecast the next hour.

    The demand follows the daily pattern, the weather, and disturbances that last a few hours: each hour's disturbance keeps 70% of the previous hour's, plus new random noise (an AR(1) process, short for autoregressive of order 1).

    Split by time. Train on the first 150 days and test on the last 50 days (\(50 \times 24 = 1200\) forecasts). For forecasting, never split at random: a random split lets the model see the hours just after the ones it predicts, which is impossible in real use. Train on the past, test on the future.

    Forecasting: the result#

    Methodtest MSE (kW\(^2\))
    Same hour yesterday45.8
    Linear model on the last 24 hours, AR(24)13.7
    Recurrent network (GRU, 929 parameters)11.6
    Noise floor (unpredictable part)9.0
    • The naive forecast (“same hour yesterday”) ignores the current disturbance.
    • The AR(24) model, a linear regression on the last 24 values (Lecture 2), uses it and does far better.
    • The GRU does somewhat better still.
    • No model can beat 9.0 kW\(^2\): the new noise each hour is unpredictable.

    ISLP reaches a similar conclusion on stock-market data: recurrent networks help only modestly over a good linear autoregressive model.

    Worked numbers

    GRU with 16 hidden units and 1 input: \(3 \times (16 \times 1 + 16 \times 16 + 16 + 16) = 3 \times 304 = 912\) parameters (three gates, each with input weights, recurrent weights and two bias vectors), plus the output \(16 + 1 = 17\): 929.
