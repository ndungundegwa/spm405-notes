    When to use deep learning#

    The three examples of this lecture show three different outcomes: networks lost on a table of sensor readings, won decisively on images, and helped modestly on a time series. This page draws the lessons.

    Where deep learning shines, and where it does not#

    Deep learning shines with:

    • images, sound, vibration signals and text;
    • raw inputs where you do not know the right features;
    • large data sets.

    Try simpler models first when:

    • the data are a table of measured features (on the six-sensor machines, the random forest won);
    • the data set is small;
    • you must be able to explain the model.

    Occam's razor (ISLP Section 10.6): if a simpler model does about as well, prefer it.

    Things to watch#

    • Standardise the inputs. For images: subtract the mean pixel value and divide by the standard deviation.
    • Keep a validation set for early stopping and for choosing the architecture (number of layers and units); keep the test set for the very end.
    • Randomness: results change with the seed and with the library version. Fix the seed, and report the spread over a few seeds.
    • Start small: a small network that trains beats a big one that does not.
    • Hardware: small networks run on an ordinary processor (CPU). For large images use a graphics card (GPU); Google Colab offers one free (Runtime → Change runtime type → GPU; then move the model and data to "cuda" in PyTorch).

    Summary of Lecture 7#

    1. A neural network stacks linear models with non-linear activations between them.
    2. It is fitted by gradient descent, with gradients from backpropagation, in minibatches.
    3. Networks overfit easily: use dropout, weight decay or early stopping.
    4. Convolutional networks share small filters across an image; recurrent networks carry a memory along a sequence.
    5. On tables of features, try trees and linear models first.
