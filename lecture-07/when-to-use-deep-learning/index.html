    When to use deep learning#

    When to use deep learning#

    Deep learning shines: images, sound, vibration signals, text; raw inputs where you do not know the right features; large datasets

    Try simpler models first: a table of measured features (our machines: the forest won); small datasets; when you must explain the model

    Occam's razor (ISLP 10.6): if a simpler model does about as well, prefer it

    Today's three examples show all three cases: networks lost on a table, won decisively on images, and helped modestly on a sequence.

    Things to watch#

    Standardise the inputs (images: subtract the mean, divide by the standard deviation)

    Keep a validation set for early stopping and for choosing the architecture; keep the test set for the end

    Randomness: results change with the seed and the library version. Fix the seed; report the spread over a few seeds

    Start small: a small network that works beats a big one that does not train

    Hardware: small networks run on a CPU; for large images use Colab's free GPU

    In Colab: Runtime, Change runtime type, GPU; then move the model and data to "cuda".

    Summary#

    1. A neural network stacks linear models with non-linear activations between them
    1. It is fitted by gradient descent, with gradients from backpropagation, in minibatches
    1. Networks overfit easily: use dropout, weight decay or early stopping
    1. Convolutional networks share small filters across an image; recurrent networks carry memory along a sequence
    1. On tables of features, try trees and linear models first
